# Trademark Search and Filing Plan

## What was actually done in this pass

An **informal public web search** was run for "Inaya" / "Inaya Network" in a software/blockchain/crypto context, to catch any obvious, already-visible conflict before spending time or money on a formal search. It found no direct software, crypto, or blockchain company operating under a confusingly similar "Inaya Network" name. It also confirmed the correct official channel for Pakistan: **IPO-Pakistan's Trademark Registry** (`ipo.gov.pk/trademark_registry`).

**This is not a clearance search.** "Inaya" is a common name across South Asia and the Muslim world, in wide use by unrelated businesses (clothing, hospitality, healthcare, etc., in categories that don't compete with software/blockchain). A real clearance search checks the *actual* Pakistani trademark register for conflicting marks *specifically in the relevant classes* (see below) — an informal web search cannot substitute for that, and this plan does not claim it does.

## Recommended Nice Classification Classes

Pakistan uses the international Nice Classification. Based on what Inaya actually is (a decentralized storage protocol, a SaaS Business Workspace, mobile/desktop apps, and blockchain/DeFi-adjacent services), the classes most likely relevant are:

| Class | Covers | Relevance |
|---|---|---|
| **9** | Downloadable software, computer programs, mobile apps | Core — the SDK, desktop/mobile apps |
| **42** | SaaS, software design/development, cloud computing, platform-as-a-service | Core — the Business Workspace, storage protocol, hosted services |
| **36** | Financial services (may cover certain blockchain/token-related services, depending on IPO-Pakistan's current classification practice) | Likely relevant given staking, corporate escrow, and token-related functionality |
| **38** | Telecommunications (data transmission services) | Possibly relevant for the storage/network protocol itself |

**This class selection is a starting point for counsel to confirm, not a final filing decision.** Pakistan's classification practice for blockchain-specific goods/services should be checked directly with IPO-Pakistan or counsel, since this is a newer area of practice.

## Filing Sequence

1. **Formal register search** — counsel or a registered trademark agent runs the actual IPO-Pakistan register search for INAYA / INAYA NETWORK across the classes above. Only after this should filing proceed.
2. **Priority filing decision** — file the word marks first (broader protection, cheaper); decide separately whether the logo needs its own device-mark filing based on how much the visual mark itself (versus the name) matters to the brand.
3. **File through IPO-Pakistan** (`ipo.gov.pk`) — directly or through a registered trademark agent, per standard Pakistani practice.
4. **Monitor for opposition** during the statutory opposition period after publication.
5. **Renewal calendar** — once registered, add renewal deadlines to the Ongoing IP Evidence Repository (Phase 7) so they're never missed.

## Open Question for the User

Should trademark protection also be pursued outside Pakistan (e.g., in markets where Inaya actively operates or has users)? The SOW's stated jurisdiction is Pakistan only — this plan stays within that scope, but international filing (via the Madrid Protocol, if Pakistan is a member, or direct national filings) is worth a deliberate yes/no decision rather than a default.
